## Commands

```bash
npm run dev       # Start dev server at localhost:3000
npm run build     # Production build (also runs next-sitemap in production)
npm run lint      # ESLint via Next.js
npm run start     # Start production server
```

No test suite is configured.

## Architecture

**Next.js 15 App Router** project for 360 Eyecare, a Toronto optometry clinic with two locations (Beaches and Yorkville/Rosedale).

### Route Groups

The `app/` directory uses route groups to organize pages by domain, none of which affect the URL path:

- `(blog)` — Blog with `[...slug]` catch-all that fetches from the WordPress REST API
- `(contact)` — Booking, virtual consult, direct billing, and consent form pages
- `(eye-care)` — Clinical service pages (dry eye, laser vision, orthokeratology, etc.)
- `(eye-ware)` — Eyewear pages (contact lenses, sunglasses, custom lenses, selection guide)
- `(locations)` — Location-specific landing pages (Toronto Beaches)
- `(marketing)` — Standalone marketing pages (Yorkville consultation, thank-you); these pages hide the NavBar/Footer
- `(our-team)` — Team and careers pages
- `(quick-links)` — Legal/policy pages

### Layout & Navigation

`app/layout.js` sets up fonts (Poppins, Roboto, Lora, Figtree), Google Analytics, and global JSON-LD schema markup. It delegates to `app/RootLayout2.jsx`, which conditionally hides `NavBar` and `Footer` for `/shop/`, `/book-eye-consultation-yorkville`, and `/thank-you`.

### Central Data Store

`constants/Constants.js` is the primary content source — almost all static copy, service descriptions, FAQ arrays, team bios, and structured data for components is exported from here. Changes to page content nearly always go here rather than in component files.

`constants/Images.jsx` is the single source for all image imports. Add new images here and re-export them; pages and components import from this file rather than directly from `public/`.

### Components

`components/` holds all page-section components (named after what they display). Reusable primitives are in `components/common/`. Radix UI primitives are wrapped in `components/components/ui/`.

### API Routes

Five form endpoints in `app/api/`, all using **nodemailer** to send emails via SMTP. All forms require a Google reCAPTCHA token verified server-side. The contact form routes email to location-specific addresses based on which clinic is selected.

### Blog Integration

Blog posts are fetched server-side from a WordPress REST API. The base URL is set via `NEXT_PUBLIC_BLOG_BASE_URL`. The `blogService.js` strips `/dashboard/` from WordPress URLs to produce clean canonical paths (matching the `next.config.mjs` redirect rule).

### Styling

Tailwind CSS with a custom design system defined in `tailwind.config.js`. Key brand tokens:
- `combination-100` — `#40BCC8` (teal, used for links and accent elements)
- `combination-200` — `#204060` (dark blue, used for buttons)
- `brand.blue` — `#28305F`, `brand.darkBlue` — `#034D76`

### SEO

Every page exports a `metadata` object with title, description, Open Graph, Twitter Card, and canonical URL. The root layout injects organization/business JSON-LD schema. Sitemap is auto-generated by `next-sitemap` on production builds.

### Deployment

Pushes to `main` trigger a GitHub Actions workflow that SSH-deploys to a VPS: `git pull`, `npm install`, then `pm2 restart 360eyecare`.

### Required Environment Variables

```
NEXT_PUBLIC_BLOG_BASE_URL      # WordPress REST API base (e.g. https://example.com/wp-json/wp/v2)
RECAPTCHA_SECRET_KEY           # Google reCAPTCHA v2 secret
EMAIL_SERVER_HOST
EMAIL_SERVER_PORT
EMAIL_SERVER_SECURE            # "true" or "false"
EMAIL_SERVER_USER
EMAIL_SERVER_PASSWORD
EMAIL_FROM
EMAIL_TO                       # Default recipient
FOR_BEACHES_LOCATION           # Email for Beaches clinic submissions
FOR_YORKVILLE_LOCATION         # Email for Yorkville/Rosedale clinic submissions
```
